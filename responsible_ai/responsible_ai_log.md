# NetSage AI — Responsible AI Documentation

## 1. Purpose and Scope

NetSage AI is an AI-assisted network troubleshooting system designed to support troubleshooting of Cisco Packet Tracer and Cisco-style network laboratories.

The system uses artificial intelligence to analyze network symptoms, topology information, command output, and deterministic rule-checker findings. Its purpose is to assist a human reviewer in identifying possible network faults and appropriate troubleshooting steps.

NetSage AI is an assistance system, not an autonomous network configuration system.

The AI does not directly modify routers, switches, PCs, or network configurations.

---

## 2. Human-in-the-Loop Design

Human oversight is a core requirement of NetSage AI.

The system separates the workflow into:

1. Network case selection
2. Evidence collection
3. Rule checking
4. AI diagnosis
5. Human review
6. Verification
7. Audit logging

An AI-generated diagnosis is considered a recommendation rather than an approved result.

The reviewer can:

- Accept the diagnosis
- Edit the diagnosis
- Reject the diagnosis

A diagnosis must pass through human review before it can proceed to verification.

This prevents an AI-generated recommendation from automatically becoming an approved troubleshooting action.

---

## 3. Separation of AI and Deterministic Logic

NetSage AI uses both deterministic logic and generative AI.

The deterministic rule checker is responsible for identifying known network conditions that can be established from explicit rules and supplied configuration data.

The AI is responsible for interpreting the available information and presenting a structured troubleshooting diagnosis.

When the rule checker produces a finding, that finding is treated as authoritative for the identified condition.

The AI may provide additional explanation, evidence, or troubleshooting recommendations, but it must not override the deterministic root cause.

This architecture reduces the risk of an AI model contradicting a known rule-based network finding.

---

## 4. Evidence Grounding

The AI receives information from the troubleshooting case, including:

- Symptoms
- Topology
- Show command output
- Rule checker findings
- Expected OSI layer information

The prompts explicitly instruct the model to use supplied evidence when forming its diagnosis.

The system instructs the AI not to invent:

- IP addresses
- Subnet masks
- Default gateways
- Interfaces
- Routes
- Command output
- Other configuration values

If a required network value is not known, the AI is instructed to refer to it generically.

This reduces the possibility of presenting fabricated network information as observed evidence.

---

## 5. Structured AI Output

NetSage AI requires the model to return a JSON object containing:

- `root_cause`
- `confidence`
- `evidence`
- `osi_layer`
- `next_command`
- `fix_steps`

The backend validates the returned structure before accepting the AI response.

Evidence and fix steps must be represented as lists.

Invalid or malformed AI responses are rejected rather than being treated as valid diagnoses.

This provides a controlled interface between the generative AI service and the rest of the application.

---

## 6. Confidence Handling

The AI uses three confidence levels:

- Low
- Medium
- High

The prompt instructs the AI to lower its confidence when the supplied evidence is insufficient.

Confidence is intended to communicate the strength of the available evidence rather than guarantee that a diagnosis is correct.

A high-confidence response still requires human review.

---

## 7. Safe Troubleshooting Recommendations

NetSage AI is instructed to diagnose the fault before recommending a correction.

The AI is also instructed to recommend safe Cisco troubleshooting steps and avoid claiming that a fix has already been applied.

The system does not automatically execute commands generated by the AI.

Fix steps displayed by the dashboard are recommendations only.

A reviewer can therefore evaluate the recommendation before it is accepted.

---

## 8. Human Review

The human review stage provides three possible decisions:

### Accepted

The reviewer agrees with the AI diagnosis.

The reviewed diagnosis can proceed to verification.

### Edited

The reviewer modifies the diagnosis before approval.

The edited result becomes the human-reviewed result rather than silently replacing the original AI output.

### Rejected

The reviewer determines that the diagnosis should not be accepted.

Rejected diagnoses are blocked from successful verification.

Reviewer notes can be recorded to provide additional context for the decision.

---

## 9. Verification

Verification occurs after human review.

The system distinguishes between:

- Pending
- Approved
- Blocked

An accepted or edited diagnosis can proceed toward approval.

A rejected diagnosis is blocked.

This provides an additional control layer between AI generation and an approved troubleshooting result.

---

## 10. AI Failure Handling

NetSage AI is designed to continue operating when the external AI service is unavailable or produces an unusable response.

Examples of AI service failures include:

- API quota exhaustion
- API errors
- Invalid JSON
- Empty responses
- Invalid response structures
- Other runtime exceptions

When an AI response cannot be safely used, the system falls back to deterministic diagnosis logic.

This prevents an external AI service failure from causing the entire troubleshooting workflow to fail.

The fallback does not pretend that a failed AI request was successful.

---

## 11. API Credential Protection

The Gemini API credential is stored through environment configuration rather than being hard-coded into application source code.

The `.env` file is excluded from Git through `.gitignore`.

The repository contains `.env.example` for documenting the required configuration without exposing the actual API credential.

API credentials must never be committed to the repository.

---

## 12. Auditability

NetSage AI records relevant workflow information through backend logs.

The project contains logging for:

- AI runs
- Human review decisions
- Verification results

These records provide an audit trail showing how a diagnosis moved through the system.

The separation between AI output, human review, and verification makes it possible to distinguish between what the model recommended and what the human reviewer approved.

---

## 13. Data Minimization and Privacy

NetSage AI is designed primarily for educational network troubleshooting cases.

Users should avoid submitting unnecessary sensitive or confidential information to the AI service.

Network information submitted to an external AI provider should be limited to information required for the troubleshooting task.

API credentials and other secrets must not be included in troubleshooting cases, prompts, logs, or source-controlled files.

---

## 14. Known Limitations

NetSage AI has several limitations.

### AI Accuracy

The AI can produce incorrect interpretations even when its response is structurally valid.

A valid JSON response does not guarantee a correct diagnosis.

### Limited Evidence

If the supplied case does not contain enough information, the system may not be able to determine the actual fault.

### External API Dependency

Gemini availability depends on the configured API service, model availability, quotas, and network connectivity.

### Rule Coverage

The deterministic checker can only identify conditions covered by its implemented rules.

### Educational Scope

The system is intended for network troubleshooting education and controlled laboratory environments. It should not be treated as an autonomous production-network management system.

---

## 15. Testing and Validation

The project contains automated tests covering the major components of the system.

The test suite includes:

- AI service tests
- Application/API tests
- Rejection workflow tests
- Rule checker tests
- Human review tests
- Verification tests

The system is expected to pass the automated test suite before final delivery.

Testing verifies both normal operation and important safety-related behavior, including rejection and fallback handling.

---

## 16. Responsible Use

NetSage AI should be used as a decision-support tool.

Users should:

- Review the evidence supporting a diagnosis.
- Verify that recommended commands are appropriate.
- Check AI-generated conclusions against the available network information.
- Use the human review stage rather than treating AI output as automatically correct.
- Avoid providing secrets or unnecessary sensitive information.
- Treat fix steps as recommendations rather than confirmation that a configuration change occurred.

The system should not be used to justify an unexplained network configuration change solely because an AI model recommended it.

---

## 17. Responsible AI Design Summary

NetSage AI applies the following principles:

| Principle | Implementation |
|---|---|
| Human oversight | Every diagnosis passes through human review |
| Transparency | AI diagnosis, review, and verification are separate stages |
| Evidence grounding | AI is instructed to use supplied case evidence |
| Hallucination reduction | Prompts prohibit invented network information |
| Deterministic safeguards | Rule checker findings are authoritative |
| Structured output | AI responses are validated against a defined schema |
| Safe operation | AI cannot directly modify network configurations |
| Failure handling | Deterministic fallback is used when AI processing fails |
| Auditability | AI, review, and verification information is logged |
| Credential protection | API secrets are stored in environment configuration |
| Appropriate use | System is positioned as educational decision support |

---

## 18. Final Statement

NetSage AI is designed around the principle that generative AI should assist network troubleshooting rather than replace human judgment.

The combination of deterministic network rules, evidence-grounded AI analysis, structured output validation, human review, verification, and audit logging provides multiple safeguards against treating an AI recommendation as an unquestionable result.

The final troubleshooting decision remains under human control.
